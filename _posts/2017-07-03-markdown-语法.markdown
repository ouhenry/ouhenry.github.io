Markdown 适合把注意力放在内容上：用少量标记表达结构，让笔记既容易编辑，也方便发布。这里整理博客写作中常用的语法，替代早期附带的英文编辑器示例。

## 用标题组织内容

文章标题由头部元数据中的 `title` 提供。正文从二级标题开始，让目录层级清楚。

```markdown
## 一个完整的主题

先说明要讨论的问题。

### 这个主题下的细节

再补充实现过程或具体例子。
```

标题标记后要留一个空格。尽量让标题说明这一节的内容，而不是只写“介绍”或“其他”。

## 段落与强调

空一行开始新段落。行内用一对星号表示强调，两对星号表示粗体。

```markdown
这是第一段，先交代背景。

这是第二段，用 **粗体** 标出关键概念，用 *斜体* 表示强调。
```

短段落更适合屏幕阅读，也方便之后补充或修改。

## 列表与步骤

信息并列时使用无序列表；有先后关系时使用有序列表。

```markdown
- 输入：算法接收的数据
- 输出：算法返回的结果
- 约束：算法成立的前提

1. 准备开发环境。
2. 运行最小示例。
3. 记录结果与问题。
```

在列表前留一个空行，编号后保留空格，避免不同渲染器将列表识别成普通文本。

## 链接与图片

```markdown
[链接文字](https://jekyllrb.com/)

![图片的文字描述](/assets/images/example.png)
```

图片示例中的路径需要替换为真实文件。优先把文章配图保存到仓库，避免外部图床迁移后丢失。描述文字应说明图片表达的信息，而不只是写“图片”。

## 行内代码与代码块

变量名、函数名和命令可使用行内代码，例如 `CreateStack()`。多行示例使用围栏代码块，并注明语言。

````markdown
```c
int sum(int a, int b) {
    return a + b;
}
```
````

介绍示例前说明它解决什么问题，代码之后解释关键步骤。完整工程与局部片段要区分清楚。

## 引用与表格

引用适合放置定义或需要特别留意的说明。

```markdown
> 不积跬步，无以至千里。
```

表格适合比较多项属性，长段解释仍然放在正文里。

```markdown
| 结构 | 顺序 | 常见操作 |
| --- | --- | --- |
| 栈 | 后进先出 | 入栈、出栈 |
| 队列 | 先进先出 | 入队、出队 |
```

## 发布前回看一次

- 标题是否对应正文，章节是否有清楚的层次。
- 代码示例是否注明语言和适用条件。
- 链接是否指向实际使用的资料。
- 图片是否包含描述，手机上是否容易阅读。
- 有没有把尚未验证的猜测写成确定结论。

写作的目标是让未来的自己能够快速找回思路，也让第一次读到的人能够跟上。
